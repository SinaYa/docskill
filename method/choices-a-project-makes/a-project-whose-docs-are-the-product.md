# A project whose docs are the product

The deliverable isn't this system's documentation, so adopt narrowly or not at all.

| You found | What to settle | Who | What works |
|---|---|---|---|
| A documentation tree as the deliverable | Everything in the repo stays where it is, and `docs/` holds only new rules, quotes and decisions about how the docs are made; or don't adopt | Ask | Narrow: *by hand*. `check-docs` then leaves the deliverable alone |
| Its own entry point | `docs/` says first to start there, so there's one way in | Evidence | *By hand* |
| Its own state, decision and numbering conventions | They stay in the deliverable | Evidence | *By hand* |
| No code, and none coming | `AUTHORITY.md`'s tests section can't apply, so it stays out. If code may come, it stays in | Evidence | `--leave-out tests`: *built* |
