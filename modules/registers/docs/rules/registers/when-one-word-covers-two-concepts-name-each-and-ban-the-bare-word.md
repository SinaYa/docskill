# When one word covers two concepts, name each and ban the bare word

**When one word covers two concepts, the concepts merge in
people's heads long before anyone notices in a document.**

- If you are writing a specification, a screen label, a schema field or a commit message, these rules apply.
- A word that covered two concepts is banned unqualified. Always say which one.
- **A name must survive being read alone.** If a label only makes sense next to its
  neighbours on the screen, it will be misread everywhere else — in a notification, in a
  report, in a conversation.
- **Different concepts get different verbs**, not just different nouns.
- **Where an older name must persist**, isolate it with a scope note rather than sweeping
  every occurrence. A rename is only forced when an old term and a new term would appear
  together, in the same screen or the same document, meaning different things.
