# A run plan fixes its packages and bounds, and leaves room for what it finds

The user's words, when a run parked what it found: "you should have left room for things that anything that is found during the process. go ahead and continue your work."

- The point before the run is the git tag named in the plan.
- The lead (the main conversation) splits the work into packages, and the list is fixed. One inventory sweep runs once, at the start; what it finds is folded into existing packages.
- **One decide step and one write step per package**, each by one agent with a fixed scope, tool budget and research budget. A package that fails twice is marked *blocked*, its reason recorded, and left open.
- Write: each decision applied by the agent that made it, in waves whose target files do not overlap.
- A full check pass over all the documentation, not only what changed, then one fix round.
- **Room for findings.** Every gap found during this round that needs a decision goes to a package of its own and is **solved there**, not parked.
- Only an item that truly needs someone other than the AI stays open, each with its reason.
- **Hard stops:** all packages done → close. The lead's context at the handover limit → commit and stop.
- Agents never commit; the lead commits after each phase.
