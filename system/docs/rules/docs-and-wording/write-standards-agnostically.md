# Write standards agnostically

Standards hold regardless of the harness.

- State a rule in general language so it holds for any future case.
- Examples go in `docs/architecture/`. A rule names one only when the rule itself is about
  it.
- Write code and docs in capability terms. Never enumerate today's cases as if the list
  were final.
- After writing a rule, re-read it for wording tied to one of them.
